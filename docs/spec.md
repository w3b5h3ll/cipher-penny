# CipherPenny 需求规格（Spec）

> 状态：v0.7 草案 · 负责人：Paul · 最后更新：2026-10-05（v0.2：确定只做 Web 端，Android 以后用 Flutter，新增格式互通要求；v0.3：确定字体和视觉规范；v0.4：新增按年统计 F-STAT-4；v0.5：只记录消费支出，暂不处理收入；v0.6：新增 GitHub 私有仓库同步 F-SYNC；v0.7：新增 Android 端范围，见第 8 节）
>
> 本文档定义“做什么”和“怎样算做完”。“怎么做”见 [design.md](./design.md)，进度见 [plan.md](./plan.md)。
> 需求编号（如 `F-QA-2`）在代码、测试和 PR 描述中引用，修改需求时同步修改本文档。

## 1. 背景

现有记账 App 要么广告多、数据在厂商服务器上，要么不支持“说一句话就记一笔”。CipherPenny 是一个**个人使用、端到端加密、本地优先**的记账 Web 应用（PWA），部署在 GitHub Pages 上，支持用自然语言（包括语音听写）快速记账。

## 2. 目标与非目标

### 目标

- G1 **隐私**：账本数据只以密文形式离开内存；托管方（GitHub Pages）和任何同步端都无法读取明文。
- G2 **快速记账**：从打开应用到记下一笔，常见情况下不超过 10 秒；支持一句话记多笔。
- G3 **零运维**：纯静态站点，无后端、无数据库、无费用。
- G4 **可迁移**：加密文件格式和数据结构有语言无关的规范和测试向量（见 [vault-format.md](./vault-format.md)），后续用 Flutter 实现的 Android 应用可以读写同一份加密数据；数据可随时导出。

### 非目标（MVP 阶段明确不做）

- **收入记录**：应用只关注消费支出，界面上不提供收入的录入和统计，也不计算账户余额。数据格式仍保留 `type` 字段和收入分类（见 vault-format.md），以后恢复收入时不需要迁移数据。
- 多用户、共享账本、账号体系。
- GitHub 私有仓库以外的同步方式（WebDAV、iCloud 等）。
- 多币种、汇率换算。
- 账户之间的转账、信用卡还款、报销流程。
- 投资持仓管理。
- 自动识别支付页面（类似钱迹的自动记账）。
- iOS 专项适配（Safari 兼容、Siri、快捷指令）。
- 原生移动 App（Android 版以后用 Flutter 单独实现，不在本仓库范围内）。

## 3. 用户与场景

唯一用户：开发者本人（技术背景）。主要在桌面浏览器中使用；Flutter 版 Android 应用完成之前，手机上用 Android Chrome 打开或安装为 PWA 临时使用。

典型场景：

1. 吃完午饭，打开应用，点麦克风说“午饭 35”（或直接输入），确认保存。
2. 晚上补记一天：“早上咖啡 18，中午外卖 32，晚上打车回家 46”。
3. 每月固定的订阅（iCloud、视频会员）、房租自动入账。
4. 月底看本月支出分类占比，找出可以砍掉的订阅。
5. 换手机前导出加密备份，在新设备导入。

## 4. 功能需求

验收标准（AC）是判定“做完”的依据。标注 `[自动]` 的由单元测试覆盖，标注 `[手工]` 的在浏览器中验收。

### 4.1 保险库与加密（F-VAULT）

| 编号 | 需求 |
| --- | --- |
| F-VAULT-1 | 首次打开时创建保险库：设置主密码（至少 8 位）并二次确认，用户必须勾选“已了解忘记密码无法恢复”。 |
| F-VAULT-2 | 再次打开时输入主密码解锁；密码错误时提示错误且不泄露其他信息。 |
| F-VAULT-3 | 持久化到浏览器存储的数据全部是密文（AES-256-GCM），密钥由主密码经 KDF 派生。 |
| F-VAULT-4 | 支持手动锁定；闲置超过设定时间（默认 5 分钟，可设置 1–60 分钟或关闭）自动锁定。锁定后内存中不保留明文数据和密钥。 |
| F-VAULT-5 | 支持修改主密码，修改后旧密码失效，数据不需要重新录入。 |
| F-VAULT-6 | 支持清空本地所有数据（需二次确认）。 |

AC：
- [自动] 用正确密码能解密，用错误密码解密失败并抛出可识别的错误类型。
- [自动] 密文被篡改任意一个字节后解密失败。
- [自动] 修改密码后，新密码可解密、旧密码不可解密，数据内容不变。
- [自动] 两次加密同一份数据得到的密文不同（随机 IV）。
- [手工] 在 DevTools 的 IndexedDB 中看不到任何明文金额、备注或分类名。
- [手工] 闲置超时后回到解锁页面。

### 4.2 快速记账（F-QA）

| 编号 | 需求 |
| --- | --- |
| F-QA-1 | 首页提供一个文本输入框，接受自然语言，例如“午饭 35”“昨天打车28”。 |
| F-QA-2 | 一句话可以包含多笔，用逗号、分号、句号、换行或“然后/还有/另外”分隔。 |
| F-QA-3 | 解析出金额：支持阿拉伯数字、小数、“35块5”“5毛”、带单位的中文数字（“三十五块”“两百元”）、¥ 符号。一段里有多个数字时，优先取带货币单位的，否则取最后一个。 |
| F-QA-4 | 解析出日期：今天、昨天、前天、大前天、周X/星期X（最近一个已过去或今天的）、上周X、X月X日/号、X号；未来日期回退到上一个月或上一年。日期向后续分段延续（“昨天打车28，晚饭60”两笔都是昨天）。默认今天。 |
| F-QA-5 | 根据分类关键词自动匹配分类，最长关键词优先；出现“收到、收入、到账”等词时优先匹配收入分类；匹配不到时归入“其他”或“其他收入”。 |
| F-QA-6 | 去掉金额、日期和“花了、付了”等填充词后，剩余文字作为备注。 |
| F-QA-7 | 解析结果先以可编辑的草稿卡片展示（金额、分类、账户、日期、备注），用户确认后批量保存，也可以删除单张草稿。按 F-QA-5 判定为收入的条目不生成草稿，并提示已跳过哪几条。 |
| F-QA-8 | 浏览器支持 Web Speech API 时显示麦克风按钮，识别结果追加到输入框；不支持时提示使用输入法的语音输入。 |
| F-QA-9 | 支持通过链接 `#/add?text=<文本>` 预填输入框并直接显示草稿，方便浏览器书签或自动化工具调用。 |

AC：
- [自动] 解析器用例以语言无关的 JSON 测试向量维护（`fixtures/parser-cases.json`），覆盖上述每类金额、日期、分类、多笔和日期延续；以后的 Dart 实现跑同一份向量。
- [手工] 在 Chrome 中输入或语音说“昨天打车28，晚上和朋友吃饭260”，得到两张日期为昨天的草稿。

### 4.3 账单管理（F-TX）

| 编号 | 需求 |
| --- | --- |
| F-TX-1 | 手动新增一笔支出：金额、分类、账户、日期、备注。 |
| F-TX-2 | 首页按日期倒序分组显示当月账单，每组显示当日支出合计；可以切换月份。 |
| F-TX-3 | 点击账单进入编辑，可以修改或删除（删除需确认）。 |
| F-TX-4 | 金额以“分”为单位的整数存储，显示时保留两位小数。 |

AC：
- [自动] 金额解析与格式化往返不丢精度（如 0.1 + 0.2 场景）。
- [手工] 新增、编辑、删除后刷新页面再解锁，数据一致。

### 4.4 周期账单（F-REC）

| 编号 | 需求 |
| --- | --- |
| F-REC-1 | 创建周期支出规则：名称、金额、分类、账户、备注、频率（每 N 周/月/年）、开始日期、可选结束日期。 |
| F-REC-2 | 每次解锁时，自动为所有启用的规则补齐从上次生成到今天之间的账单（含今天），并标记来源规则。 |
| F-REC-3 | 按月的规则如果开始日是 29–31 号，在短月份取当月最后一天；按年的 2 月 29 日在平年取 2 月 28 日。 |
| F-REC-4 | 规则可以暂停、恢复、编辑和删除；恢复后不补记暂停期间的账单；删除规则不删除已生成的账单。 |
| F-REC-5 | 同一规则同一日期不会重复生成账单。 |

AC：
- [自动] 覆盖每周、每月、每年、跨月末、闰年、结束日期、重复执行幂等。

### 4.5 统计（F-STAT）

| 编号 | 需求 |
| --- | --- |
| F-STAT-1 | 按月显示总支出、笔数和日均支出（当月按已过去的天数计算，往月按整月天数，未来月份不显示日均）。 |
| F-STAT-2 | 按分类显示支出合计、笔数与占比，按金额降序，用横向条形图表示。 |
| F-STAT-3 | 按账户显示支出合计与占比（同 F-STAT-2 的形式）。 |
| F-STAT-4 | 可切换为按年统计：年度总支出、笔数和月均支出（当年按已过去的月数计算，往年按 12 个月）；12 个月的支出柱状图，点击某个月切换到该月的月度统计；按月明细表（支出、笔数、占全年比例）；全年的分类和账户占比。 |

所有统计只计入支出；数据中如有收入记录（来自旧版本或其他客户端），不参与统计，也不在账单列表中显示。

AC：
- [自动] 汇总、分类和账户排序计算正确，收入记录不计入。
- [自动] 年度统计：12 个月逐月合计之和等于全年合计；月均的月数在往年、当年、未来年份分别为 12、当前月份、0；日均的天数在往月、当月、未来月份分别为整月天数、今天的日期、0。

### 4.6 账户与分类（F-CFG）

| 编号 | 需求 |
| --- | --- |
| F-CFG-1 | 内置默认账户（现金、微信、支付宝、银行卡）和默认分类（含关键词，其中有“订阅”分类）。 |
| F-CFG-2 | 可以新增、重命名账户（即支付方式），归档账户（已有账单保留）。 |
| F-CFG-3 | 可以新增分类、修改分类的名称、图标和关键词，归档分类。 |

### 4.7 备份与导出（F-IO）

| 编号 | 需求 |
| --- | --- |
| F-IO-1 | 导出加密备份文件（与本地存储格式相同，仍需主密码才能读取）。 |
| F-IO-2 | 导入加密备份：校验格式，输入该备份的密码，解密成功并经用户确认后替换本地数据。 |
| F-IO-3 | 导出明文 CSV（UTF-8 带 BOM，方便 Excel 打开），导出前提示明文风险。 |

AC：
- [自动] 导出再导入后数据完全一致；格式错误或版本不支持的文件给出明确错误。
- [自动] 能解密仓库中固定的测试向量 `fixtures/vault-v1.json`（已知密码），保证格式不会被无意改动，并作为 Flutter 实现的互通性测试。

### 4.8 同步（F-SYNC）

同步是可选功能，不开启时应用的行为与之前完全相同。

| 编号 | 需求 |
| --- | --- |
| F-SYNC-1 | 在设置中填写 GitHub 仓库（`owner/repo`）、文件路径（默认 `vault.cpenny.json`）和 fine-grained 令牌后开启同步。开启前检查仓库存在且令牌可以访问；**公开仓库一律拒绝**。 |
| F-SYNC-2 | 同步的文件就是加密信封本身（与备份文件格式相同），远端只有密文。 |
| F-SYNC-3 | 同步时机：解锁后、本地保存后（10 秒内的多次修改合并为一次提交）、回到应用时、网络恢复时，以及手动点击“立即同步”。离线时照常记账，联网后自动补上。 |
| F-SYNC-4 | 多台设备都改过数据时自动合并，规则见 vault-format.md 第 5 节：按记录 ID 合并，同一记录取 `updatedAt` 较新的版本；删除会留下删除记录，避免被另一台设备的旧数据恢复；同一周期规则同一天生成的账单只保留一笔。合并完成后各设备数据一致。 |
| F-SYNC-5 | 在一台设备上修改主密码后，其他设备同步后改用新密码解锁。 |
| F-SYNC-6 | 新设备首次打开时可以“从 GitHub 恢复”：填写仓库、文件路径、令牌和主密码，下载并解密远端数据，同时开启同步。 |
| F-SYNC-7 | 远端文件无法用本机的数据密钥解密（属于另一个账本或已损坏）时停止同步并提示。用户可以选择用本机数据覆盖远端，或清空本机后从 GitHub 恢复。 |
| F-SYNC-8 | 令牌只保存在本机：用数据密钥加密后存入 IndexedDB，不进入同步文件和备份文件；锁定后内存中不保留令牌。断开同步只删除本机的同步配置，不动远端文件。 |
| F-SYNC-9 | 设置页显示同步状态：同步的仓库、上次同步时间、是否正在同步、失败原因（网络、令牌无效、无法解密等）。同步失败时顶栏给出提示。 |

AC：
- [自动] 合并规则以语言无关的 JSON 用例维护（`fixtures/merge-cases.json`），覆盖新增、修改、删除、删除后在另一端修改、周期账单重复生成、设置和未知字段保留；以后的 Dart 实现跑同一份用例。
- [自动] 用内存中的假远端测试同步流程：首次推送、无变化时不提交、远端有更新时合并、写入冲突后重试、远端属于另一个账本时报错并可覆盖、改密码同步到其他设备、新设备从远端恢复。
- [手工] 两个浏览器分别记账后各自同步，两边数据一致。

## 5. 非功能需求

| 编号 | 需求 |
| --- | --- |
| N-SEC-1 | 加密只使用浏览器内置 WebCrypto，不引入第三方加密库。 |
| N-SEC-2 | 生产构建通过 `<meta>` 注入严格 CSP：禁止内联脚本和第三方来源，`connect-src` 只允许 `'self'` 和同步用的 `https://api.github.com`。 |
| N-SEC-3 | 代码中禁止使用 `dangerouslySetInnerHTML`、`innerHTML`、`eval`。运行时依赖只允许 `react`、`react-dom`，新增运行时依赖需在 design.md 记录理由。 |
| N-SEC-4 | 不向任何第三方发送数据。例外：开启同步后，加密信封会发送到用户自己的 GitHub 私有仓库；Web Speech API 由浏览器厂商提供，在设置和 README 中说明其隐私影响。 |
| N-SEC-5 | 同步数据必须放在与应用代码不同的仓库中。应用代码仓库是公开的，而且同步令牌只应能写数据，不能写代码。 |
| N-OFF-1 | 安装为 PWA 后可完全离线使用。 |
| N-PERF-1 | 1 万笔账单时，解锁（不含 KDF）和保存小于 500 ms。 |
| N-UX-1 | 响应式布局：桌面端居中显示，窄屏（最小 360px）也可正常使用；支持系统深色模式。 |
| N-PORT-1 | 加密信封格式、明文数据结构、KDF 参数和解析规则以文档加测试向量的形式定义，不依赖 TypeScript 实现细节。 |
| N-UX-2 | 界面语言为简体中文。 |
| N-UX-3 | 字体：中文使用思源黑体（Noto Sans SC，与 Source Han Sans 同源），英文和数字使用 Inter，代码和技术性文本使用 JetBrains Mono。字体随站点自托管，不从第三方加载；本机已安装思源黑体时优先使用本机字体。 |
| N-UX-4 | 视觉规范参考 TDesign 的设计令牌（颜色、圆角、字号、间距、阴影），不引入组件库。 |
| N-DEP-1 | 推送到 `master` 后由 GitHub Actions 自动测试并部署到 GitHub Pages。 |

## 6. 约束

- 托管：GitHub Pages（只能托管静态文件，不能设置自定义响应头，路径前缀为 `/cipher-penny/`）。
- 浏览器：最新版 Chrome、Edge、Firefox（桌面和 Android）以及桌面版 Safari。不针对 iOS 做兼容测试。

## 7. 已确认的决定

- 2026-10-05：先做 Web 端，不做 iOS 适配；Android 端以后考虑用 Flutter 实现，与 Web 端通过加密数据格式互通。
- 2026-10-05：字体限定为思源黑体、Inter、JetBrains Mono；视觉规范参考 TDesign（理由见 design.md D9）。
- 2026-10-05：应用只关注消费支出，暂不处理收入；账户余额改为按账户统计支出。数据格式不变。
- 2026-10-05：同步使用单独的 GitHub 私有仓库（不放在公开的代码仓库里），多设备修改按单条记录自动合并（理由见 design.md D12）。

## 8. Android 端（Flutter）

Android 端与 Web 端共用第 4 节的需求编号和 vault-format.md 定义的数据格式，两端通过 F-SYNC 互通。本节只列出 Android 端的范围和差异。

| 编号 | 需求 |
| --- | --- |
| A-1 | v0.1 范围：F-VAULT-1、F-VAULT-2、F-VAULT-4、F-VAULT-6（创建、解锁、自动锁定、清空）；F-QA-1 ~ F-QA-7（文字快速记账，语音用输入法自带的语音输入）；F-TX-1 ~ F-TX-3；F-STAT-1 ~ F-STAT-4；F-REC-2、F-REC-5（解锁后补齐周期账单）；F-SYNC-1 ~ F-SYNC-9。 |
| A-2 | v0.1 暂不做：修改主密码、账户和分类管理、周期规则的增删改、备份文件导入导出、CSV、快捷链接。这些在 Web 端完成，通过同步生效。 |
| A-3 | 自动锁定：前台闲置超过 `settings.autoLockMinutes`，或切到后台超过同样时长后锁定。 |
| A-4 | 账本和同步配置只以密文保存在应用私有目录；除网络外不申请任何权限；网络请求只发往 `api.github.com`。 |
| A-5 | 加密使用 `cryptography` 包：手机上优先调用 Android 系统的 PBKDF2 和 AES-GCM 实现，测试环境使用同一包的纯 Dart 实现。 |

AC：
- [自动] Dart 测试跑通 `fixtures/` 下的全部向量：`vault-v1.json`（能解密）、`parser-cases.json`、`merge-cases.json`。
- [自动] 同步流程用假远端测试，覆盖与 Web 端相同的场景。
- [手工] 手机上“从 GitHub 恢复”后数据与 Web 端一致；两边各记一笔，同步后两边都有。

## 9. 待确认问题

1. 是否需要“恢复码”，作为忘记主密码时的后备方案？
2. 是否需要接入大模型做更强的自然语言解析（用户自备 API key）？
